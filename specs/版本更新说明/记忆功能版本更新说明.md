# LoongCode 记忆功能版本更新说明

| 项目 | 说明 |
|---|---|
| 版本 | 0.0.67 |
| 分支 | `codex-tdai-memory` |
| 日期 | 2026-09-10 |
| 本次核心能力 | 1. 内置个人记忆系统（本地优先、全自动）<br>2. 接入 TencentDB-Agent-Memory（TDAI）团队记忆能力 |

一句话总结：**LoongCode 从"每次会话都失忆"升级为"个人经验自动沉淀、团队记忆一键接入"——个人记忆零配置开箱即用，团队记忆在设置面板填一次即可，像切模型一样切换团队身份。**

---

## 一、背景：LoongCode 最初没有记忆功能

LoongCode 是基于 OpenCode 二次开发的 AI 编程助手。在本次版本之前，它**没有任何记忆能力**，具体表现为：

1. **每个会话冷启动**：回答风格偏好、技术栈习惯、各仓库的构建命令和测试约束，每个新会话都要重新交代一遍；
2. **跨会话无连续性**：昨天做到哪、为什么这么做，今天开新会话全部归零，同样的坑反复踩；
3. **多 agent 无共享记忆**：子代理会话结束后其发现随之蒸发，角色之间的结论只能靠人传话。

一句话：**每个会话都是一个没有记性的新员工，学习成本付了一遍又一遍。**

---

## 二、方案调研

### 2.1 个人记忆调研

围绕"如何让 agent 跨会话记住这个人和这些项目"，调研了两条插件路线：

| | 路线 A：opencode-codex-memory（文档形式） | 路线 B：opencode-mem（向量 RAG 形式） |
|---|---|---|
| 机制 | 两阶段自动管线：逐会话后台提炼 → git 基线 diff 整合，产出 MEMORY.md + 常驻摘要 | SQLite + 本地 embedding 模型 + 向量索引，`memory` 工具语义搜索 |
| 优点 | 全自动、无需模型自觉；记忆沉淀为技能 | 措辞漂移也能召回（"用 bun"能搜到"包管理工具"） |
| 缺点 | 插件 hook 依赖宿主版本；存在已知缺陷（作业无租约、引用标记三重冗余钩子、注入靠字节一致的技巧保缓存） | embedding 是硬依赖，不可用时语义搜索失效、新记忆写不进去；默认英文 embedding 模型对中文不友好 |

**选型结论**：以路线 A 的两阶段管线为蓝本，**内化为 LoongCode 核心功能**，而不是以第三方插件形式引入（与插件的区别详见 3.2 节）。

### 2.2 团队记忆调研

个人记忆解决"记住这个人"，团队场景还要求记忆**有隔离（防任务污染）、有交接（结论传递）、有治理（人工审核）**。调研对象是腾讯开源的 **TencentDB-Agent-Memory**（下文简称 TDAI）——一个面向 AI Agent 的长期记忆服务，具备：

- **四层记忆模型（L0–L3）**：原始对话 → 原子事实 → 场景知识块 → 长期画像，逐层沉淀、分层召回；
- **四大记忆资产**：Chat Memory（偏好与决策）、Skill（可复用技能，有版本与触发边界）、Wiki（文档知识图谱）、CodeGraph（代码符号与调用关系索引）；
- **Memory Hub 团队面板**：Team / Agent / 成员管理，资产审核、分享与配装，`private` / `team` / `restricted` 三级可见性——团队共享经验，不共享隐私；
- **官方基准**：PersonaMem 从 48% 提升到 76%（+59%）。

### 2.3 分层方案总览

最终采用三层分工，依据是**治理主体不同**：

```
┌──────────────────────────────────────────────────────┐
│ 个人记忆（偏好与经验）    本版本：LoongCode 内置记忆系统 │
├──────────────────────────────────────────────────────┤
│ 公司/项目/团队规范（静态约束） 分层 AGENTS.md，进版本库   │
├──────────────────────────────────────────────────────┤
│ 团队记忆（动态协同）      本版本：外置 TDAI 服务接入      │
└──────────────────────────────────────────────────────┘
```

规范类内容仍以 AGENTS.md 文件为权威源（人可直接编辑、进版本库共享）；个人记忆由内置系统承担；团队记忆治理交给 TDAI 的 Memory Hub。

## 三、本版本方案（一）：内置个人记忆

### 3.1 工作方式

一套**本地优先、全自动运行**的跨会话记忆能力，用户无需任何手动操作：

1. **自动学习（写路径）**——会话闲置 6 小时后，后台小模型自动把会话转录提炼成"记忆笔记"（API key、密码等秘密在进入记忆库前脱敏）；
2. **自动整合**——主模型周期性把零散笔记合并、去重、淘汰，写入一份人可读的 Markdown 记忆工作区（`MEMORY.md` + 记忆摘要 + 技能库 + 会话回顾）；用户手动编辑的记忆文件会在下一轮整合中被保留；
3. **自动召回（读路径）**——记忆摘要自动注入每个新会话的系统提示，模型也可以用 `memory_search` / `memory_read` 等工具主动检索全量记忆；对模型说"记住 X"即可显式落一条便签；
4. **引用闭环**——模型回答用到了记忆时会发出引用标记，宿主记账使用次数；30 天无人引用的记忆自动淘汰，记忆库不会变成垃圾场。

成本特性：只有写路径消耗 token（抽取用小模型、整合用主模型）；读路径（摘要注入与检索工具）零模型调用，且摘要注入不破坏模型前缀缓存。

### 3.2 与插件方案有什么不同

调研中的两条路线都是第三方插件形态。本版本选择**内化为核心功能**，差异如下：

| 维度 | 插件形态 | LoongCode 内置（本版本） |
|---|---|---|
| 安装与依赖 | 需安装第三方插件，插件 hook 依赖宿主版本，存在兼容风险 | 核心一等公民，随产品发布，零安装 |
| 配置体系 | 插件自有配置 | 统一进 `loongcode.json` 的 `memory` 配置节：配置节缺省即整体关闭，`generate_memories` / `use_memories` 可独立停写、停读，切换开关不删任何数据 |
| 读路径实现 | 靠 hook 往 system 消息追加"字节完全相同"的记忆块，规避缓存失效 | 走原生 System Context 机制，缓存分段由基线上下文的持久化机制天然保证 |
| 可靠性 | 已知缺陷：提炼作业无租约，进程被硬杀后可能悬挂 | 修正为数据库事务内 CAS 认领 + 租约机制，进程崩溃后作业只延迟、不丢失 |
| 引用闭环 | 三重冗余钩子解析引用标记 | 收敛为单一剥离点（消息持久化前），记账、去重、剥离一次完成 |
| 安全 | 依赖宿主项目边界 | 记忆子代理权限全拒绝 + 文件操作锁死在记忆目录内（路径越界守卫、拒绝 symlink 根）+ 秘密脱敏 |
| 与团队记忆的关系 | — | 与 TDAI 团队记忆可同时启用、互不干扰 |

### 3.3 使用方式与存储

- **启用**：在 `loongcode.json` 中增加 `"memory": {}` 即启用（也可带模型、闲置时长等选项）；删除该节即整体关闭，数据保留。
- **存储位置**（记忆跟着用户走，与安装形态无关，卸载重装不丢记忆）：

| 平台 | 路径 |
|---|---|
| Windows | `C:\Users\<你>\.local\share\loongcode\memory\` |
| macOS | `/Users/<你>/.local/share/loongcode/memory/` |
| Linux | `/home/<你>/.local/share/loongcode/memory/` |

  其中 `memory.db` 是作业与引用计数数据库，`memories/` 是 Markdown 记忆工作区——可 grep、可编辑、可备份（成对拷贝整个目录即可）、可彻底删除。

## 四、本版本方案（二）：团队记忆接入 TDAI

### 4.1 TDAI 是什么

TDAI（TencentDB-Agent-Memory）是腾讯开源的 AI Agent 长期记忆服务，整体由四个组件构成（官方支持一键部署三件套）：

| 组件 | 默认端口 | 职责 |
|---|---|---|
| MemoryCore | 8420 | 记忆存储与处理核心：L0–L3 分层记忆、Skill 提炼、Team/User/Agent/Task 元数据 |
| MemoryKnowledge | 8421 | 知识服务：Wiki（文档知识图谱）与 CodeGraph（代码图谱），agent 按需调用 |
| MemoryPanel | 8125 | 团队记忆控制台（Web）：团队/成员/Agent 管理，资产的登记、审核、可见性与配装 |
| MemoryProxy | 8096 | 透明 LLM 请求代理：agent 不改一行代码，把模型端点指向它即可获得记忆注入与对话回写 |

对团队协作的关键设计：

- **记忆资产按 Team + Agent 绑定**，各成员用自己的用户身份即可共享团队记忆，隐私按 `private` / `team` / `restricted` 分级隔离；
- **冷启动**：已有代码库、文档、历史会话可直接导入，自动变成 CodeGraph / Wiki / Skill 资产，新 agent"先读档，再开工"。

### 4.2 安装部署

官方一键拉起完整三件套（memory-core + memory-hub + proxy）：

```bash
git clone https://github.com/Tencent/TencentDB-Agent-Memory.git
cd TencentDB-Agent-Memory/deploy/global-images
cp .env.example .env
$EDITOR .env       # 填入两组 LLM 参数（memory 组 + proxy 组）
./start-all.sh     # 一键起
```

部署完成后：

1. 打开 Memory Hub 面板：`http://localhost:8125`；
2. 创建 Team、创建 Agent、配置成员；
3. 给 Agent 绑定资产：代码库（→ CodeGraph）、文档（→ Wiki）、历史对话（→ Skill 与 Chat Memory）；
4. 此后每次对话会自动注入该 Agent 的团队记忆，并把新对话写回。

### 4.3 如果没有这次 LoongCode 改版，怎么集成

TDAI 的接入原理是**透明代理**：把 LoongCode 的模型请求端点指向 MemoryProxy（默认 8096 端口），代理在 LLM 调用层自动完成团队记忆的召回注入与对话写回，代理通过 4 个身份头（`x-team-id` / `x-agent-id` / `x-task-id` / `x-conversation-id`）识别"这次请求属于哪个团队、哪个 agent 身份"。

改版前的唯一接法是：**在 `loongcode.json` 里为每一个 TDAI 身份手工编写一个完整的 provider 条目**——

- 每个条目都要重复 baseURL、apiKey 和整份模型列表，**只有 4 个身份头的值不同**；
- 换一个身份就要再复制一整个近似的 provider 块，条目数量随身份线性增长；
- 全靠手工编辑 JSON，易错且难维护；模型选择器里会出现一堆名字相近的重复项；
- API key 明文散落在每个条目里。

这种接法繁琐、易错、无法规模化管理，普通用户基本无法独立完成。

### 4.4 这次改版之后怎么集成

本版本为 TDAI 接入做了原生适配（实验性功能，未配置时对产品完全无感）：

1. **设置界面新增 TDAI (Beta) 面板**：代理地址、API Key、模型列表**只填一次**；添加身份（agent）时只填一个名字和 4 个身份头的值，不再复制任何 provider 块；
2. **身份即模型条目**：每个 TDAI 身份以独立条目出现在模型选择器中（桌面端与 TUI 均支持），**像切换模型一样切换团队身份**；
3. **会话内随时切换**：一个会话可以在同一任务中以不同 TDAI 身份工作；身份选择按会话持久化，重启/恢复会话不丢；
4. **切换零代价**：只换身份不换模型时，不重建上下文基线（Context Epoch），切换成本极低；连带换模型则遵循普通换模型规则；
5. **配置可托管**：全部 TDAI 配置存于全局配置的 `experimental.tdai` 节，可由托管配置统一下发给团队；
6. **配套健壮性修复**：支持 `tdai/<身份>` 形式带斜杠的模型标识解析（`parseModel` 特殊处理），并对含 `/` 的非法身份键给出警告并安全跳过。

集成后的使用流程：**部署 TDAI → 设置面板填一次连接信息 → 添加团队成员的身份 → 模型选择器里选身份开始工作**，此后团队记忆的注入与写回全自动。

## 五、已知边界

- 个人记忆为**全局单份**存储（跨项目共享，带项目来源标签），刻意不做项目分区；团队/多角色记忆治理由 TDAI 承担；
- 内置记忆写路径由后台作业完成，进程刚被硬杀时记忆"迟到不丢失"（durable 状态是权威，最坏延迟到下次启动）；
- TDAI 侧当前版本：私有仓库 CodeGraph 导入仍在完善、面板暂不支持记忆内容编辑（可通过 API）、上游 LLM 仅能通过配置文件设定；
