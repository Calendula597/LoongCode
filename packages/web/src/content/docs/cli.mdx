The LoongCode CLI by default starts the [TUI](/docs/tui) when run without any arguments.

```bash
loongcode
```

But it also accepts commands as documented on this page. This allows you to interact with LoongCode programmatically.

```bash
loongcode run "Explain how closures work in JavaScript"
```

---

### tui

Start the LoongCode terminal user interface.

```bash
loongcode [project]
```

#### Flags

| Flag                                        | Short | Description                                                             |
| ------------------------------------------- | ----- | ----------------------------------------------------------------------- |
| <nobr><code>{"--continue"}</code></nobr>    | `-c`  | Continue the last session                                               |
| <nobr><code>{"--session"}</code></nobr>     | `-s`  | Session ID to continue                                                  |
| <nobr><code>{"--fork"}</code></nobr>        |       | Fork the session when continuing (use with `--continue` or `--session`) |
| <nobr><code>{"--prompt"}</code></nobr>      |       | Prompt to use                                                           |
| <nobr><code>{"--model"}</code></nobr>       | `-m`  | Model to use in the form of provider/model                              |
| <nobr><code>{"--agent"}</code></nobr>       |       | Agent to use                                                            |
| <nobr><code>{"--auto"}</code></nobr>        |       | Auto-approve permissions that are not explicitly denied                 |
| <nobr><code>{"--port"}</code></nobr>        |       | Port to listen on                                                       |
| <nobr><code>{"--hostname"}</code></nobr>    |       | Hostname to listen on                                                   |
| <nobr><code>{"--mdns"}</code></nobr>        |       | Enable mDNS discovery                                                   |
| <nobr><code>{"--mdns-domain"}</code></nobr> |       | Custom mDNS domain name                                                 |
| <nobr><code>{"--cors"}</code></nobr>        |       | Additional browser origin(s) to allow CORS                              |

## Commands

The LoongCode CLI also has the following commands.

---

### agent

Manage agents for LoongCode.

```bash
loongcode agent [command]
```

---

#### create

Create a new agent with custom configuration.

```bash
loongcode agent create
```

This command will guide you through creating a new agent with a custom system prompt and permission configuration. Anything you don't allow is denied in the generated agent's frontmatter.

#### Flags

| Flag                                        | Short | Description                                                                                                                                                                                                                |
| ------------------------------------------- | ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <nobr><code>{"--path"}</code></nobr>        |       | Directory to write the agent file to (defaults to global or `.loongcode/agent` based on the prompt)                                                                                                                         |
| <nobr><code>{"--description"}</code></nobr> |       | What the agent should do                                                                                                                                                                                                   |
| <nobr><code>{"--mode"}</code></nobr>        |       | Agent mode: `all`, `primary`, or `subagent`                                                                                                                                                                                |
| <nobr><code>{"--permissions"}</code></nobr> |       | Comma-separated list of permissions to allow (default: all). Available: `bash`, `read`, `edit`, `glob`, `grep`, `webfetch`, `task`, `todowrite`, `websearch`, `lsp`, `skill`. Anything omitted is denied. Alias: `--tools` |
| <nobr><code>{"--model"}</code></nobr>       | `-m`  | Model to use, in `provider/model` format                                                                                                                                                                                   |

Passing all of `--path`, `--description`, `--mode`, and `--permissions` runs the command non-interactively.

---

#### list

List all available agents.

```bash
loongcode agent list
```

### attach

Attach a terminal to an already running LoongCode backend server started via `serve` or `web` commands.

```bash
loongcode attach [url]
```

This allows using the TUI with a remote LoongCode backend. For example:

```bash
# Start the backend server for web/mobile access
loongcode web --port 4096 --hostname 0.0.0.0

# In another terminal, attach the TUI to the running backend
loongcode attach http://10.20.30.40:4096
```

#### Flags

| Flag                                     | Short | Description                                                                |
| ---------------------------------------- | ----- | -------------------------------------------------------------------------- |
| <nobr><code>{"--dir"}</code></nobr>      |       | Working directory to start TUI in                                          |
| <nobr><code>{"--continue"}</code></nobr> | `-c`  | Continue the last session                                                  |
| <nobr><code>{"--session"}</code></nobr>  | `-s`  | Session ID to continue                                                     |
| <nobr><code>{"--fork"}</code></nobr>     |       | Fork the session when continuing (use with `--continue` or `--session`)    |
| <nobr><code>{"--password"}</code></nobr> | `-p`  | Basic auth password (defaults to `LOONGCODE_SERVER_PASSWORD`)              |
| <nobr><code>{"--username"}</code></nobr> | `-u`  | Basic auth username (defaults to `LOONGCODE_SERVER_USERNAME` or `loongcode`) |

### auth

Command to manage credentials and login for providers.

```bash
loongcode auth [command]
```

---

#### login

LoongCode is powered by the provider list at [Models.dev](https://models.dev), so you can use `loongcode auth login` to configure API keys for any provider you'd like to use. This is stored in `~/.local/share/loongcode/auth.json`.

```bash
loongcode auth login
```

When LoongCode starts up it loads the providers from the credentials file. And if there are any keys defined in your environments or a `.env` file in your project.

##### Flags

| Flag                                     | Short | Description                                          |
| ---------------------------------------- | ----- | ---------------------------------------------------- |
| <nobr><code>{"--provider"}</code></nobr> | `-p`  | Provider ID or name to log in to                     |
| <nobr><code>{"--method"}</code></nobr>   | `-m`  | Login method label to use, skipping method selection |

---

#### list

Lists all the authenticated providers as stored in the credentials file.

```bash
loongcode auth list
```

Or the short version.

```bash
loongcode auth ls
```

---

#### logout

Logs you out of a provider by clearing it from the credentials file.

```bash
loongcode auth logout
```

### mcp

Manage Model Context Protocol servers.

```bash
loongcode mcp [command]
```

---

#### add

Add an MCP server to your configuration.

```bash
loongcode mcp add
```

This command will guide you through adding either a local or remote MCP server.

---

#### list

List all configured MCP servers and their connection status.

```bash
loongcode mcp list
```

Or use the short version.

```bash
loongcode mcp ls
```

---

#### auth

Authenticate with an OAuth-enabled MCP server.

```bash
loongcode mcp auth [name]
```

If you don't provide a server name, you'll be prompted to select from available OAuth-capable servers.

You can also list OAuth-capable servers and their authentication status.

```bash
loongcode mcp auth list
```

Or use the short version.

```bash
loongcode mcp auth ls
```

---

#### logout

Remove OAuth credentials for an MCP server.

```bash
loongcode mcp logout [name]
```

---

#### debug

Debug OAuth connection issues for an MCP server.

```bash
loongcode mcp debug <name>
```

### models

List all available models from configured providers.

```bash
loongcode models [provider]
```

This command displays all models available across your configured providers in the format `provider/model`.

This is useful for figuring out the exact model name to use in [your config](/docs/config/).

You can optionally pass a provider ID to filter models by that provider.

```bash
loongcode models anthropic
```

#### Flags

| Flag                                    | Description                                                  |
| --------------------------------------- | ------------------------------------------------------------ |
| <nobr><code>{"--refresh"}</code></nobr> | Refresh the models cache from models.dev                     |
| <nobr><code>{"--verbose"}</code></nobr> | Use more verbose model output (includes metadata like costs) |

Use the `--refresh` flag to update the cached model list. This is useful when new models have been added to a provider and you want to see them in LoongCode.

```bash
loongcode models --refresh
```

### run

Run loongcode in non-interactive mode by passing a prompt directly.

```bash
loongcode run [message..]
```

This is useful for scripting, automation, or when you want a quick answer without launching the full TUI. For example.

```bash "loongcode run"
loongcode run Explain the use of context in Go
```

You can also attach to a running `loongcode serve` instance to avoid MCP server cold boot times on every run:

```bash
# Start a headless server in one terminal
loongcode serve

# In another terminal, run commands that attach to it
loongcode run --attach http://localhost:4096 "Explain async/await in JavaScript"
```

#### Flags

| Flag                                     | Short | Description                                                                |
| ---------------------------------------- | ----- | -------------------------------------------------------------------------- |
| <nobr><code>{"--command"}</code></nobr>  |       | The command to run, use message for args                                   |
| <nobr><code>{"--continue"}</code></nobr> | `-c`  | Continue the last session                                                  |
| <nobr><code>{"--session"}</code></nobr>  | `-s`  | Session ID to continue                                                     |
| <nobr><code>{"--fork"}</code></nobr>     |       | Fork the session when continuing (use with `--continue` or `--session`)    |
| <nobr><code>{"--share"}</code></nobr>    |       | Share the session                                                          |
| <nobr><code>{"--model"}</code></nobr>    | `-m`  | Model to use in the form of provider/model                                 |
| <nobr><code>{"--agent"}</code></nobr>    |       | Agent to use                                                               |
| <nobr><code>{"--file"}</code></nobr>     | `-f`  | File(s) to attach to message                                               |
| <nobr><code>{"--format"}</code></nobr>   |       | Format: default (formatted) or json (raw JSON events)                      |
| <nobr><code>{"--title"}</code></nobr>    |       | Title for the session (uses truncated prompt if no value provided)         |
| <nobr><code>{"--attach"}</code></nobr>   |       | Attach to a running loongcode server (e.g., http://localhost:4096)         |
| <nobr><code>{"--password"}</code></nobr> | `-p`  | Basic auth password (defaults to `LOONGCODE_SERVER_PASSWORD`)              |
| <nobr><code>{"--username"}</code></nobr> | `-u`  | Basic auth username (defaults to `LOONGCODE_SERVER_USERNAME` or `loongcode`) |
| <nobr><code>{"--dir"}</code></nobr>      |       | Directory to run in, or path on the remote server when attaching           |
| <nobr><code>{"--port"}</code></nobr>     |       | Port for the local server (defaults to random port)                        |
| <nobr><code>{"--variant"}</code></nobr>  |       | Model variant (provider-specific reasoning effort)                         |
| <nobr><code>{"--thinking"}</code></nobr> |       | Show thinking blocks                                                       |
| <nobr><code>{"--auto"}</code></nobr>     |       | Auto-approve permissions that are not explicitly denied                    |

```bash

```

This starts an HTTP server that provides API access to loongcode functionality without the TUI interface. Set `LOONGCODE_SERVER_PASSWORD` to enable HTTP basic auth (username defaults to `loongcode`).

#### Flags

| Flag                                        | Description                                |

| <nobr><code>{"--hostname"}</code></nobr>    | Hostname to listen on                      |
| <nobr><code>{"--mdns"}</code></nobr>        | Enable mDNS discovery                      |
| <nobr><code>{"--mdns-domain"}</code></nobr> | Custom mDNS domain name                    |


## Environment variables

LoongCode can be configured using environment variables.

| Variable                              | Type    | Description                                       |
| ------------------------------------- | ------- | ------------------------------------------------- |
| `LOONGCODE_AUTO_SHARE`                | boolean | Automatically share sessions                      |
| `LOONGCODE_GIT_BASH_PATH`             | string  | Path to Git Bash executable on Windows            |
| `LOONGCODE_CONFIG`                    | string  | Path to config file                               |
| `LOONGCODE_TUI_CONFIG`                | string  | Path to TUI config file                           |
| `LOONGCODE_CONFIG_DIR`                | string  | Path to config directory                          |
| `LOONGCODE_CONFIG_CONTENT`            | string  | Inline json config content                        |
| `LOONGCODE_DISABLE_AUTOUPDATE`        | boolean | Disable automatic update checks                   |
| `LOONGCODE_DISABLE_PRUNE`             | boolean | Disable pruning of old data                       |
| `LOONGCODE_DISABLE_TERMINAL_TITLE`    | boolean | Disable automatic terminal title updates          |
| `LOONGCODE_PERMISSION`                | string  | Inlined json permissions config                   |
| `LOONGCODE_DISABLE_DEFAULT_PLUGINS`   | boolean | Disable default plugins                           |
| `LOONGCODE_DISABLE_LSP_DOWNLOAD`      | boolean | Disable automatic LSP server downloads            |
| `LOONGCODE_ENABLE_EXPERIMENTAL_MODELS` | boolean | Enable experimental models                       |
| `LOONGCODE_DISABLE_AUTOCOMPACT`       | boolean | Disable automatic context compaction              |
| `LOONGCODE_DISABLE_CLAUDE_CODE`       | boolean | Disable reading from `.claude` (prompt + skills)  |
| `LOONGCODE_DISABLE_CLAUDE_CODE_PROMPT` | boolean | Disable reading `~/.claude/CLAUDE.md`             |
| `LOONGCODE_DISABLE_CLAUDE_CODE_SKILLS` | boolean | Disable loading `.claude/skills`                  |
| `LOONGCODE_DISABLE_MODELS_FETCH`      | boolean | Disable fetching models from remote sources       |
| `LOONGCODE_DISABLE_MOUSE`             | boolean | Disable mouse capture in the TUI                  |
| `LOONGCODE_FAKE_VCS`                  | string  | Fake VCS provider for testing purposes            |
| `LOONGCODE_CLIENT`                    | string  | Client identifier (defaults to `cli`)             |
| `LOONGCODE_ENABLE_EXA`                | boolean | Enable Exa web search tools                       |
| `LOONGCODE_ENABLE_PARALLEL`           | boolean | Enable Parallel web search tools                  |
| `LOONGCODE_SERVER_PASSWORD`           | string  | Enable basic auth for `serve`/`web`               |
| `LOONGCODE_SERVER_USERNAME`           | string  | Override basic auth username (default `loongcode`) |
| `LOONGCODE_MODELS_URL`                | string  | Custom URL for fetching models configuration      |
